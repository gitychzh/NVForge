## 2. 决策: NOP (不改参数)

**理由:**

1. **SR=97.8% (30min)**, **BJT 高峰各小时 98.1-98.8%** — 均远超 95% 干预阈值。
2. **3 个 zombie 全部是 1 分钟窗口内 (13:53-13:54 UTC) 的瞬态洪峰** — 不是持续性劣化, 不是特定 key 问题。之后的请求全部 200 成功。
3. **24h ATE 从 248→189, 下降 23.8%** — 系统正在自然改善, 参数不必要调整。
4. **6h zombie 均匀分布** — 每小时 1-4 个, 随机散布在 5 个 key 上。NVCF 上游的偶发空响应, 无法通过参数调整消除。
5. **0 fallback, 0 429** — 系统级指标健康。
6. **P95 改善 2.6s** (26.7s→24.1s) — 正常请求的尾部延迟在下降。
7. **Per-key k3/k4 延迟稍高但稳定** — 这是 NVCF 特定 key 的固有特性, EMPTY_200_FASTBREAK=3 正常处理了偶发 zombie。调整该参数(如升至 5) 会加延迟速返回, 但不会改善 SR (因为 zombie 无法通过重试消除, 它们是上游空响应而非重试可恢复超时)。
8. **BJT 晚间高峰验证成功** — R1106 只验证了凌晨低负载。本轮确认高压时段同样稳定。

**结论**: NOP — BJT 晚间高峰 SR 稳定在 98%+, 0 fallback, 0 429, ATE 持续下降。无需参数修改。
